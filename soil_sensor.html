ESP32 Soil Sensor & Automatic Watering → InfluxDB → Grafana

A small plant-monitoring and watering system: an ESP32 in a printed weatherproof box reads an RS485 soil probe every five minutes, pushes the readings to InfluxDB Cloud, plots them on a public Grafana dashboard, and runs a 12 V pump through a drip ring when the soil gets dry.

Open the live dashboard ↗

Overview

I wanted a no-fuss way to keep an eye on soil moisture and temperature for a potted lime tree on the patio — and then to water it automatically — without running a server at home. The whole stack is hosted: the microcontroller talks straight to InfluxDB Cloud over HTTPS, and Grafana Cloud reads from InfluxDB and serves a dashboard I can share with a link. Nothing to maintain beyond the ESP32 itself.

The Grafana dashboard: soil moisture (%) and soil temperature (°C), one point every five minutes. Live version.

Hardware

The probe is a generic sealed RS485 soil moisture and temperature sensor that speaks Modbus RTU at 4800 baud. It exposes two holding registers — moisture and temperature, each scaled by 10 — so a single Modbus read returns both values. The ESP32 talks to it through a MAX13487-based RS485-to-TTL board on UART2 (GPIO 16/17), with GPIO 4 driving the DE/RE pin to switch between transmit and receive around each request, and a bidirectional logic level converter between the 3.3 V ESP32 and the 5 V RS485 board. The ModbusMaster library handles the framing; the two preTransmission/postTransmission callbacks in the sketch just toggle that direction pin.

Logging to InfluxDB

InfluxDB's Arduino client (InfluxDbClient) does most of the work. On boot the ESP32 joins WiFi, syncs its clock over NTP (the InfluxDB Cloud TLS certificate can't be validated without correct time), and checks the connection to the bucket. Each reading is a single Point in the soilSensor measurement with two tags — the device type and the WiFi SSID — and two fields, Soil Moisture and Soil Temperature. The point is serialized to InfluxDB line protocol and written with one HTTPS call, then the loop sleeps for five minutes. That cadence is plenty for soil, and keeps the write volume comfortably inside the free tier.

The bucket name, org ID, and API token live in #defines at the top of the sketch (redacted in the copy below). The token should be a write-only token scoped to the one bucket, so a leaked device can't read anything back.

Pulling the data into Grafana

Grafana Cloud connects to InfluxDB Cloud as a data source using the Flux query language, with the InfluxDB URL, org, and a read token. Each dashboard panel is a short Flux query that selects the measurement and field and lets Grafana pick the aggregation window to match the zoom level:

from(bucket: "PlantLogger")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r["_measurement"] == "soilSensor")
  |> filter(fn: (r) => r["_field"] == "Soil Moisture")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)

Two time-series panels — one per field — and the dashboard is done. Grafana's public dashboards feature turns it into a read-only page that anyone with the link can view, which is what the button at the top of this page points at.

Automatic watering

With the readings already in hand every cycle, closing the loop is cheap: a 12 V pump, switched by a MOSFET from an ESP32 pin, waters the tree whenever the soil is drier than a threshold. Everything a person would want to tune is a #define at the top of the sketch — the pump pin, the moisture threshold, how many seconds to run the pump per dose, the minimum gap between doses (so the water has time to soak down to the probe before the next reading decides it's still dry), and a daily cap on waterings as a safety net if the probe ever fails low. The pump is only allowed to run on a successful Modbus read; a failed read logs a flag and does nothing. A quiet-hours window (10 pm to 8 am by default, using the NTP-synced local clock) blocks watering overnight, and if the clock hasn't synced yet the sketch assumes quiet hours rather than guessing. Pump seconds and the day's watering count are written to InfluxDB alongside the readings, so each dose shows up on the dashboard next to the moisture curve it caused.

The pump and the drip ring. The first version used a small peristaltic pump, which was fine for a houseplant but far too slow for a tree in a big pot outdoors. It was replaced with a SEAFLO 21-series 12 V diaphragm pump (1.2 GPM, self-priming, happy to run dry if the reservoir empties) feeding a loop of ¼ in drip line with pressure-compensating emitters laid around the trunk, so each dose spreads evenly across the whole root ball instead of soaking one spot. The pump draws 3–4 A running and several times that for a few tens of milliseconds at startup, which is why the power section below is fussier than the sketch.

The drip ring and probe in the lime tree's pot, with the diaphragm pump and tubing being test-fitted before it all went into the box.

Driving the pump. A logic-level N-channel MOSFET (IRLZ44N) as a low-side switch: pump between +12 V and the drain, source to ground, gate to GPIO 18 with a 10 kΩ pull-down so the pump stays off while the ESP32 boots. A flyback diode goes across the pump's two terminals, banded end to the +12 V side — and only there; across the supply or in parallel with the MOSFET it either shorts the supply or bypasses the switch and runs the pump continuously, which is a mistake I made exactly once. The pump's 4 A return path gets its own heavy wire straight to the supply's negative terminal rather than sharing a perf-board trace with the logic ground, so the inrush can't lift the ESP32's ground reference.

Power, and a lesson about brownouts. The box takes 12 V in, with a 7805 linear regulator dropping it to 5 V for the ESP32 dev board and the RS485 transceiver. The first time the diaphragm pump was connected, the board booted, finished joining WiFi, took its first reading of a probe sitting in open air (0%), and fired the pump — whose inrush sagged the 12 V rail below the 7805's dropout, browned out the ESP32, and rebooted it. A reboot wipes every software interlock, so it did the same thing again every 20 seconds. Two fixes: a 1000 µF electrolytic across the regulator's input (plus the usual 0.1 µF ceramics) to carry it through the inrush, and a set of guards in the sketch — a soft-start ramp on the pump, a lockout if the last reset was a brownout, a sanity floor on the reading, and a 60 s arming delay after boot. The reset reason and uptime are logged with every point, so a flaky supply shows up on the dashboard instead of silently cycling.

Keeping a peristaltic pump quiet. This no longer matters with the diaphragm pump (it runs at 100% duty), but it's still in the sketch for anyone using a small peristaltic one indoors. Those whine at full speed, so the MOSFET gate can be driven with 25 kHz PWM from the ESP32's LEDC peripheral rather than switched hard on. PUMP_DUTY_PERCENT sets the speed — around half duty is dramatically quieter, and the dose is made up with a longer PUMP_ON_SECONDS. The soft-start ramp gets the brushed motor turning before it settles at the low duty, and the PWM frequency sits above hearing range so the switching itself adds no tone. One gotcha: a big MOSFET like the IRLZ44N has a lot of gate charge, and a 3.3 V GPIO through a 1 kΩ gate resistor can't switch it fast enough at 25 kHz — the motor stalls at any duty below 100%. The fix is a small gate resistor (47–100 Ω) and setting the pin to its maximum 40 mA drive strength, which the sketch does in pumpSetup().

Wireless updates. The sketch also enables ArduinoOTA, so after the first USB flash the board shows up under Tools → Port → Network ports in the Arduino IDE and later uploads go over WiFi. The five-minute wait between readings (and the pump run) is a loop that keeps servicing OTA rather than a blocking delay(), and the OTA start callback drops the pump pin low so an upload can never leave the pump running.

The enclosure

Everything lives on a piece of perf board inside a box I modeled in Fusion and printed in white PETG, since it sits outside on the patio in Texas sun and rain. The lid has a groove for a printed TPU gasket and screws down on four heat-set inserts, with mounting ears at the corners. On one end wall are a cable gland for the probe lead and two panel-mount jacks — 12 V in and the pump out — so the box can be unplugged without opening it. A rectangular cutout on the other end lines up with the ESP32's USB port for the first flash and serial debugging, and a matching TPU plug seals it the rest of the time; every later upload goes over WiFi. Inside, the ESP32 dev board, the RS485 transceiver, the level shifter, the 7805 and its capacitors, and the pump MOSFET share one perf board, with the pump's heavy leads kept off it.

Code

The full ESP32 sketch, including the watering logic. Fill in your own WiFi credentials, InfluxDB org, and token, and set the OTA password, pump pin, threshold, and run time in the block of #defines at the top before flashing.

Watering only fires on a valid reading, and then only after a chain of interlocks: a sanity floor on the reading (a probe sitting in air reads 0%), a lockout if the last reset was a brownout (a sign the pump's inrush dragged the supply down and rebooted the board), a 60 s arming delay after boot, quiet hours overnight, a minimum interval between waterings, and a daily cap. The pump soft-starts over half a second to spread out its inrush, and the reset reason and uptime are logged with every point so a flaky supply shows up on the dashboard.

ESP32 sketch — soil_pump.ino
// ESP32 soil sensor -> InfluxDB Cloud, with automatic watering.
// Reads an RS485 Modbus soil moisture/temperature probe, logs to InfluxDB,
// and runs a 12 V pump (via a MOSFET) when the soil is drier than a threshold.

#if defined(ESP32)
  #include <WiFiMulti.h>
  WiFiMulti wifiMulti;
  #define DEVICE "ESP32"
#elif defined(ESP8266)
  #include <ESP8266WiFiMulti.h>
  ESP8266WiFiMulti wifiMulti;
  #define DEVICE "ESP8266"
#endif

#include <InfluxDbClient.h>
#include <InfluxDbCloud.h>
#include <ModbusMaster.h>
#include <ArduinoOTA.h>
#include <driver/gpio.h>       // gpio_set_drive_capability
#include <esp_system.h>        // esp_reset_reason

// ---- WiFi / InfluxDB ----
#define WIFI_SSID "your-wifi-ssid"
#define WIFI_PASSWORD "your-wifi-password"
#define INFLUXDB_URL "https://us-east-1-1.aws.cloud2.influxdata.com"
#define INFLUXDB_TOKEN "your-influxdb-api-token"
#define INFLUXDB_ORG "your-influxdb-org-id"
#define INFLUXDB_BUCKET "PlantLogger"
#define TZ_INFO "CST6CDT,M3.2.0,M11.1.0"   // US Central with DST (POSIX format)

// ---- Over-the-air updates ----
// After the first USB upload, the board appears under Tools > Port > Network ports as OTA_HOSTNAME.
#define OTA_HOSTNAME "soil-sensor"
#define OTA_PASSWORD "change-me"      // the IDE asks for this before a wireless upload

// ---- Watering configuration (edit these) ----
#define PUMP_PIN 18                  // GPIO driving the pump MOSFET gate (low-side N-channel, e.g. IRLZ44N)
#define MOISTURE_THRESHOLD 20.0      // % soil moisture: water when a reading is below this
#define MOISTURE_MIN_VALID 1.0       // readings below this are treated as "probe not in soil" and never water
#define PUMP_ON_SECONDS 10           // how long to run the pump per watering
#define PUMP_DUTY_PERCENT 100        // pump speed, 0-100. A diaphragm pump should run at 100; lower only for a small peristaltic
#define PUMP_RAMP_MS 500             // soft-start: ramp from 0 to PUMP_DUTY_PERCENT over this time to limit inrush
#define PUMP_PWM_HZ 25000            // above hearing range, so the PWM itself doesn't whine
#define MIN_WATER_INTERVAL_MIN 60    // minimum time between waterings, so water can soak in
#define MAX_WATERINGS_PER_DAY 6      // safety cap in case the probe reads low or fails
#define QUIET_START_HOUR 22          // no watering from this hour (24h clock, local time)...
#define QUIET_END_HOUR 8             // ...until this hour
#define ARM_DELAY_SEC 60             // no watering in the first N seconds after boot (bench-test / reboot-loop guard)
#define READ_INTERVAL_MIN 5          // minutes between sensor readings

// ---- RS485 / Modbus ----
#define RXD2 16
#define TXD2 17
#define RS485_DE_RE 4
HardwareSerial RS485Serial(2);       // UART2
ModbusMaster node;

InfluxDBClient client(INFLUXDB_URL, INFLUXDB_ORG, INFLUXDB_BUCKET, INFLUXDB_TOKEN, InfluxDbCloud2CACert);
Point sensor("soilSensor");

// Watering state
unsigned long lastWaterMillis = 0;
bool hasWatered = false;
int wateringsToday = 0;
unsigned long dayStartMillis = 0;
unsigned long bootMillis = 0;
esp_reset_reason_t resetReason = ESP_RST_UNKNOWN;
bool wateringLocked = false;         // set when the last reset was a brownout: no watering until a clean reboot

const char* resetReasonName(esp_reset_reason_t r) {
  switch (r) {
    case ESP_RST_POWERON:  return "poweron";
    case ESP_RST_SW:       return "software";
    case ESP_RST_PANIC:    return "panic";
    case ESP_RST_INT_WDT:  return "int_wdt";
    case ESP_RST_TASK_WDT: return "task_wdt";
    case ESP_RST_WDT:      return "wdt";
    case ESP_RST_DEEPSLEEP:return "deepsleep";
    case ESP_RST_BROWNOUT: return "brownout";
    case ESP_RST_SDIO:     return "sdio";
    default:               return "unknown";
  }
}

void preTransmission()  { digitalWrite(RS485_DE_RE, HIGH); }
void postTransmission() { digitalWrite(RS485_DE_RE, LOW); }

// ---- Pump PWM (ESP32 LEDC peripheral) ----
// Works with both the 2.x and 3.x esp32 Arduino cores, whose LEDC APIs differ.
#define PUMP_PWM_BITS 8
#define PUMP_PWM_CHANNEL 0
void pumpSetup() {
  // Max drive strength (40 mA) so the pin can charge a big MOSFET gate quickly enough for 25 kHz PWM.
  // Pair this with a 10k gate pull-down (keeps the pump off while the ESP32 is in reset) and a
  // flyback diode across the pump terminals, banded end to +12 V.
  gpio_set_drive_capability((gpio_num_t)PUMP_PIN, GPIO_DRIVE_CAP_3);
#if defined(ESP_ARDUINO_VERSION_MAJOR) && ESP_ARDUINO_VERSION_MAJOR >= 3
  ledcAttach(PUMP_PIN, PUMP_PWM_HZ, PUMP_PWM_BITS);
#else
  ledcSetup(PUMP_PWM_CHANNEL, PUMP_PWM_HZ, PUMP_PWM_BITS);
  ledcAttachPin(PUMP_PIN, PUMP_PWM_CHANNEL);
#endif
}
void pumpSet(int percent) {
  percent = constrain(percent, 0, 100);
  uint32_t duty = (uint32_t)percent * ((1u << PUMP_PWM_BITS) - 1) / 100u;
#if defined(ESP_ARDUINO_VERSION_MAJOR) && ESP_ARDUINO_VERSION_MAJOR >= 3
  ledcWrite(PUMP_PIN, duty);
#else
  ledcWrite(PUMP_PWM_CHANNEL, duty);
#endif
}
void pumpOff() { pumpSet(0); }

void setup() {
  // Pump off before anything else, so it can't run during boot
  pinMode(PUMP_PIN, OUTPUT);
  digitalWrite(PUMP_PIN, LOW);
  pumpSetup();
  pumpOff();

  Serial.begin(115200);
  bootMillis = millis();

  // A brownout reset usually means the pump's inrush dragged the supply down and rebooted us.
  // Since a reset wipes the interval/daily-cap state, lock watering out until a clean power cycle
  // so a marginal supply can't cause a reboot loop. The reason is logged to InfluxDB each cycle.
  resetReason = esp_reset_reason();
  Serial.printf("Reset reason: %s\n", resetReasonName(resetReason));
  if (resetReason == ESP_RST_BROWNOUT) {
    wateringLocked = true;
    Serial.println("Last reset was a BROWNOUT - watering locked out until the next clean power-on");
  }

  WiFi.mode(WIFI_STA);
  wifiMulti.addAP(WIFI_SSID, WIFI_PASSWORD);
  Serial.print("Connecting to wifi");
  while (wifiMulti.run() != WL_CONNECTED) {
    Serial.print(".");
    delay(100);
  }
  Serial.println();

  // Accurate time is needed for TLS certificate validation
  timeSync(TZ_INFO, "pool.ntp.org", "time.nis.gov");

  if (client.validateConnection()) {
    Serial.print("Connected to InfluxDB: ");
    Serial.println(client.getServerUrl());
  } else {
    Serial.print("InfluxDB connection failed: ");
    Serial.println(client.getLastErrorMessage());
  }

  sensor.addTag("device", DEVICE);
  sensor.addTag("SSID", WiFi.SSID());

  // OTA: make sure the pump is off if an upload interrupts a watering
  ArduinoOTA.setHostname(OTA_HOSTNAME);
  ArduinoOTA.setPassword(OTA_PASSWORD);
  ArduinoOTA.onStart([]() { pumpOff(); Serial.println("OTA update starting"); });
  ArduinoOTA.onEnd([]()   { Serial.println("\nOTA update done, rebooting"); });
  ArduinoOTA.onError([](ota_error_t e) { Serial.printf("OTA error %u\n", e); });
  ArduinoOTA.begin();
  Serial.printf("OTA ready: %s at %s\n", OTA_HOSTNAME, WiFi.localIP().toString().c_str());

  pinMode(RS485_DE_RE, OUTPUT);
  digitalWrite(RS485_DE_RE, LOW);
  RS485Serial.begin(4800, SERIAL_8N1, RXD2, TXD2);
  node.begin(1, RS485Serial);
  node.preTransmission(preTransmission);
  node.postTransmission(postTransmission);

  dayStartMillis = millis();
}

// Wait for the given number of milliseconds while keeping OTA (and WiFi) serviced.
// A plain delay() would leave the board unreachable for wireless uploads.
void waitAndServiceOTA(unsigned long ms) {
  unsigned long start = millis();
  while (millis() - start < ms) {
    ArduinoOTA.handle();
    delay(10);
  }
}

// Run the pump for PUMP_ON_SECONDS at PUMP_DUTY_PERCENT, then stop.
// Soft-start: ramp the duty up over PUMP_RAMP_MS so the motor's inrush is spread out
// instead of hitting the 12 V supply as a step (which can brown out the ESP32).
void runPump() {
  Serial.printf("Watering: pump on for %d s at %d%% (ramp %d ms)\n", PUMP_ON_SECONDS, PUMP_DUTY_PERCENT, PUMP_RAMP_MS);
  const int steps = 20;
  for (int i = 1; i <= steps; i++) {
    pumpSet(PUMP_DUTY_PERCENT * i / steps);
    waitAndServiceOTA(PUMP_RAMP_MS / steps);
  }
  waitAndServiceOTA((unsigned long)PUMP_ON_SECONDS * 1000UL);
  pumpOff();
  lastWaterMillis = millis();
  hasWatered = true;
  wateringsToday++;
}

// True during the no-watering window. If the clock isn't set yet, err on the side of not watering.
bool inQuietHours() {
  struct tm t;
  if (!getLocalTime(&t, 50)) {
    Serial.println("Local time not available - treating as quiet hours");
    return true;
  }
  int h = t.tm_hour;
  if (QUIET_START_HOUR > QUIET_END_HOUR)          // window wraps past midnight, e.g. 22 -> 8
    return h >= QUIET_START_HOUR || h < QUIET_END_HOUR;
  return h >= QUIET_START_HOUR && h < QUIET_END_HOUR;
}

// Decide whether to water given a valid moisture reading.
// Returns the number of seconds pumped (0 or PUMP_ON_SECONDS).
int maybeWater(float moisture) {
  // Roll the daily counter every 24 h
  if (millis() - dayStartMillis >= 24UL * 60UL * 60UL * 1000UL) {
    dayStartMillis = millis();
    wateringsToday = 0;
  }
  if (moisture >= MOISTURE_THRESHOLD) return 0;

  // ---- Safety interlocks, cheapest first ----
  if (moisture < MOISTURE_MIN_VALID) {
    Serial.printf("Moisture %.1f%% is below %.1f%% - probe probably not in soil, not watering\n", moisture, (double)MOISTURE_MIN_VALID);
    return 0;
  }
  if (wateringLocked) {
    Serial.println("Soil is dry, but watering is locked out after a brownout reset - check the 12 V supply");
    return 0;
  }
  if (millis() - bootMillis < (unsigned long)ARM_DELAY_SEC * 1000UL) {
    Serial.printf("Soil is dry, but we booted < %d s ago - not armed yet\n", ARM_DELAY_SEC);
    return 0;
  }
  if (inQuietHours()) {
    Serial.printf("Soil is dry, but it's quiet hours (%02d:00-%02d:00) - not watering\n", QUIET_START_HOUR, QUIET_END_HOUR);
    return 0;
  }
  if (hasWatered && (millis() - lastWaterMillis) < (unsigned long)MIN_WATER_INTERVAL_MIN * 60UL * 1000UL) {
    Serial.println("Soil is dry, but the last watering was too recent - waiting");
    return 0;
  }
  if (wateringsToday >= MAX_WATERINGS_PER_DAY) {
    Serial.println("Soil is dry, but the daily watering cap is reached - not watering");
    return 0;
  }
  runPump();
  return PUMP_ON_SECONDS;
}

void loop() {
  float humidity = 0, temperature = 0;
  bool readOk = false;
  int pumpedSeconds = 0;

  uint8_t result = node.readHoldingRegisters(0x0000, 2);
  if (result == node.ku8MBSuccess) {
    humidity = node.getResponseBuffer(0) / 10.0;
    temperature = node.getResponseBuffer(1) / 10.0;
    readOk = true;
    Serial.printf("Moisture: %.1f %%, Temp: %.1f C\n", humidity, temperature);
  } else {
    Serial.printf("Modbus read failed (code %d) - no watering this cycle\n", result);
  }

  // Only ever water on a good reading
  if (readOk) {
    pumpedSeconds = maybeWater(humidity);
  }

  // Build the InfluxDB point. Tags stay; fields are cleared each cycle.
  sensor.clearFields();
  if (readOk) {
    sensor.addField("Soil Moisture", humidity);
    sensor.addField("Soil Temperature", temperature);
  }
  sensor.addField("Pump Seconds", pumpedSeconds);
  sensor.addField("Waterings Today", wateringsToday);
  sensor.addField("Read OK", readOk ? 1 : 0);
  sensor.addField("Brownout", resetReason == ESP_RST_BROWNOUT ? 1 : 0);
  sensor.addField("Uptime Min", (int)(millis() / 60000UL));

  Serial.print("Writing: ");
  Serial.println(sensor.toLineProtocol());

  if (wifiMulti.run() != WL_CONNECTED) {
    Serial.println("Wifi connection lost");
  }
  if (!client.writePoint(sensor)) {
    Serial.print("InfluxDB write failed: ");
    Serial.println(client.getLastErrorMessage());
  }

  Serial.printf("Waiting %d minutes (OTA stays available)\n\n", READ_INTERVAL_MIN);
  waitAndServiceOTA((unsigned long)READ_INTERVAL_MIN * 60UL * 1000UL);
}
